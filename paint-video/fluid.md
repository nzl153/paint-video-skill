# 流体彩墨 MV：让音符直接推动墨和颜料

想要画面「活起来」、不讲具体故事、跟着音乐一下一下动的 MV 时，读这份。

范例是《一滴墨》：91 秒，D 小调，古典引子 → 摇滚砸进来 → 中段静下来 → 高潮 → 主题回来 → 小提琴独自收尾。画面是一张纸上的墨和彩墨在流动，没有人物，也没有镜头。代码在本仓库的 `fluid-kit/`，配乐的做法见 `music.md` 的「古典 + 摇滚」一节。

## 什么时候选这套

- 前几套画风的共同毛病是容易做成「动态 PPT」：一张静画，加推镜，再淡入淡出。这套的画面每一帧都在变，而且每一下变化都对得上一个音符。
- 不画演奏的人。手和指法是代码画动画最弱的地方，画得不对比不画更糟。让音乐本身变成画面：小提琴是一支笔，鼓是打进水里的冲击，镲是一次开花。
- 抽象不等于随便。每种乐器有固定的画法，每一段有固定的「水性」，观众看几遍就能对上：「这一下是底鼓」。

## 管线

1. 乐谱里每个音符都记一笔：`[乐器, 音名, 秒, 时值, 力度]` 推进 `window.EV`。`node tools/audio.mjs --events` 导出成 `src/events.json`。**改了乐谱就要重导**，画面才跟得上。
2. `src/mv.js` 读音符表，按乐器和时间排成一张事件表：哪一秒、在哪、加什么颜料、给多大的力。
3. 流体逐帧推进，每帧拍一张 JPEG，ffmpeg 合上混好的音轨。

画面不按拍写、直接按秒写，因为这首曲子从头到尾一个速度（120）。曲子要变速的话，参照 `music.md`「对画面」一节先做拍和秒的换算。

## 流体引擎

- WebGL2 稳定流体（Stam 的 stable fluids）：速度场 480×270，颜料场 1920×1080；每帧两个子步，压力 Jacobi 迭代 30 次，涡量约束让小漩涡不被抹平，另加一层随时间变的噪声力，静止时也在缓缓流。
- 浮点纹理要开 `EXT_color_buffer_float` 和 `OES_texture_float_linear`。
- **流体有状态，帧只能从头顺序推进**，不能多进程乱序并行。看第 60 秒的静帧也要从 0 秒模拟过去（`--at` 就是这么做的）。RTX 4060 笔记本上约 65 ms/帧，91 秒约 3 分钟。
- 无头 Chrome 要带 `--ignore-gpu-blocklist`，不然可能落到软件渲染，慢十几倍。
- 墨滴往下落靠一段时间内的重力 `uG`，用推力推不动它。

## 颜料按「吸光度」存

颜料场存的不是颜色，而是 r、g、b 三个通道各吸掉多少光。显示时 `颜色 = 纸色 × exp(−A)`。

- 每种颜料的吸光度从色板反推：`A = −ln(颜色 / 纸色)`。《一滴墨》用了墨、陶土、靛蓝、赭石四种。
- 好处是叠在一起会自然变深，像真颜料：陶土压在赭石上是更深的橙，墨压在任何颜色上都是更深的墨。加法混色做不到这一点，会越叠越亮、越叠越灰。
- 浓淡交界处按浓度梯度压暗一点，挤出一道深边，像颜料干了以后的边。薄的地方透出纸纹。
- 叠得太多会发黑，显示时软压一下：`A /= 1 + 0.3 * max(0, 浓度 − 1.2)`。
- **靛蓝和暖色（陶土、赭石）叠在同一处，就是一片棕黑的泥。** 一次炸开里只放冷色加一种暖色，别三种全上；当前和弦的颜色是靛蓝时尤其要注意。

## 乐器怎么变成画面

| 声音 | 画面 |
|---|---|
| 独奏小提琴 | 一支笔。音高定高低，一行 8 秒从左写到右，写满换行。每一小步补一个中点，否则快的时候线会断成一串珠子 |
| 大提琴、小提琴跳弓 | 画面上下两排小墨点 |
| 竖琴 | 零星几粒墨点 |
| 底鼓 | 一次冲击，加三粒当前和弦的颜色。颜色点在冲击的外圈，让漩涡把它拉成旋臂；点在正中心会留下一枚圆片 |
| 军鼓 | 横着抽一道 |
| 踩镲 | 画面下方的赭黄细点 |
| 嗵鼓过门 | 围着中心转一圈的冲击 |
| 镲渐强、滚奏 | 往中心吸，像吸一口气 |
| 镲 | 一次开花（见「炸法」） |
| 长和弦 | 一团颜色慢慢洇开 |

**和弦决定颜色**：Dm、Gm 是靛蓝，B♭、C 是陶土，F、A 是赭石。和声一换，画面的主色就跟着换。

## 每一段是一种「水性」

段落的差别主要靠流体参数，而不是换画法：

- **安静段**（古典引子、中段、尾声）：噪声力小、涡量小，颜料几乎不褪（褪色系数 0.01，约每秒 1%），墨慢慢晕开。
- **摇滚段**：噪声力和涡量都调大，褪色系数 0.06（约每秒 6%），不然画面很快被填满。
- **高潮和最后的重击**：褪色系数 0.14（约每秒 13%），否则颜色越叠越浑。到 0.16 又淡得炸不起来。
- **换段时冲淡**：中段开头在 3 秒里把整张颜料淡到 0.22，像被水冲开；主题回来前冲淡一半再上色。
- **齐奏停住的那一下**：在 0.36 秒里每个模拟小步都把速度场乘 0.8，整幅画几乎定住。
- **尾声**：颜料淡回纸色，小提琴在白纸上写最后一句，最后一滴墨落在中心，和开头呼应。

## 炸法：每一次开花都不一样

高潮每小节一记镲，8 记都用同一种炸法会很单调。`mv.js` 里有 7 种，高潮按顺序轮换：

| 炸法 | 做法 |
|---|---|
| `bloomBurst` 开花 | 7 个偏开的小冲击，加几瓣颜色往外甩。正中心不上色 |
| `collide` 对撞 | 两股颜色从两侧冲向同一点，撞处挤出深边 |
| `spiral` 旋臂 | 颜色顺着几条螺旋臂甩出去 |
| `fan` 扇泼 | 从画面一侧朝里泼出一扇 |
| `crown` 皇冠 | 一圈小水花同时往外溅，读起来是「多个点同时炸开」 |
| `slash` 切割 | 一刀切过去，刀口两边反向错开，卷出一排浪花 |
| `plume` 升腾 | 从下往上冲一柱，顶上翻成蘑菇 |

- 一个大冲击只会炸成一枚正圆盘，像橡皮擦擦过。多个偏开的小冲击加不对称的颜色才像泼出去的。
- 冲击别加旋转。加了会留下一圈圈同心纹，像盖了个章。
- 扇泼要是每条射线都点颜色，颜色会在源头堆成一团黑；只点一半的射线。
- 颜料的半径宁小勿大：半径翻倍，面积是四倍，一下就铺成一大片。

## 检查

- 静帧：`node tools/render.mjs --at=16.5,48.5,56.5,79.7` 出几张拼成联系表。每次都从头模拟，所以多要几张也不贵。
- **看炸法要看连续的几个时刻**：每一下取炸开后 0.15、0.4、0.9 秒三张，看它是不是读得出形状，有没有圆片、盖章圈、黑泥。
- 帧差扫描：整片渲完后算相邻帧的平均差。最大值是中位数的 3 倍以内、而且分散在连续几帧上，就不会闪；单独一帧跳起来就是闪。
- 帧多，联系表只能抽样，整片按正常速度放一遍才知道节奏对不对。

## 出片

```bash
node tools/audio.mjs --stems               # 参考版 + 五组分轨
python -I tools/mixdesk.py music/mix.py    # 混音 → out/yidimo_mix.wav
node tools/render.mjs --audio=out/yidimo_mix.wav
```

改了 `mv.js` 再出片，要换一个 `--frames` 目录或先把旧帧挪走。
